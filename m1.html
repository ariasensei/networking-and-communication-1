II. Introduction to Computer Networking

Computer networking is the process of connecting two or more computers or devices so they can communicate and share resources.

A network allows devices to share:

Data Files Internet Printers Applications Servers
Message Created → Data Prepared → Destination Identified → Data Sent → Transmitted → Response Received

III. Why Do We Need Network Models?

Without standards and models, different hardware, operating systems, and protocols would struggle to communicate. A network model provides a structured way to understand how network communication works.

Benefits:

  • Understand network communication
  • Design networks
  • Develop network protocols
  • Troubleshoot network problems
  • Allow different technologies to work together
  • Standardize communication processes

IV. The OSI Model

OSI = Open Systems Interconnection

A conceptual framework by ISO describing how data communication occurs between networked systems, divided into seven layers.

7 Application Network services to apps
6 Presentation Translate, encrypt, compress
5 Session Manage sessions
4 Transport End-to-end delivery
3 Network Logical addressing & routing
2 Data Link Frames & MAC addresses
1 Physical Raw bits over medium

Mnemonic (7→1): All People Seem To Need Data Processing

Mnemonic (1→7): Please Do Not Throw Sausage Pizza Away

Layer 7 – Application

Provides network-related services directly to software applications. It does not mean the application itself — it provides services that allow applications to communicate over a network.

Protocols

HTTP, HTTPS, FTP, SMTP, DNS, DHCP, SSH

Examples

Web browsing, Email, File transfer, Name resolution

Layer 6 – Presentation

Responsible for how data is represented or formatted. Performs data translation, encryption/decryption, compression/decompression, and character encoding.

Translation Encryption Compression Encoding

Layer 5 – Session

Establishes, manages, and terminates communication sessions between applications. A session is a logical conversation between two systems.

Establish Maintain Synchronize Terminate

Layer 4 – Transport

Provides end-to-end communication between applications on different devices. Responsible for segmentation, reassembly, flow control, error recovery, and port addressing.

TCP

Reliable, connection-oriented. Establishes connections, numbers segments, retransmits lost data, ensures order.

UDP

Connectionless, low overhead. Useful when speed matters more than guaranteed delivery.

Port examples: HTTP=80 | HTTPS=443 | DNS=53

Layer 3 – Network

Responsible for logical addressing and routing. Determines how packets travel from one network to another.

Functions

Logical addressing, routing, path selection, packet forwarding

Key Protocol & Device

IP (IPv4/IPv6) • Router

e.g. 192.168.1.10

Layer 2 – Data Link

Responsible for communication over a local network link. Organizes data into frames and uses MAC addresses for local delivery.

Functions

Framing, MAC addressing, error detection, media access control

Devices & Address

Switches, Bridges

MAC: 00:1A:2B:3C:4D:5E

Layer 1 – Physical

The lowest layer. Deals with actual transmission of bits (0s and 1s) over a physical or wireless medium.

UTP Cable Fiber-optic Coaxial Wireless RJ-45 Hubs Repeaters

VII–IX. Encapsulation & Decapsulation

Encapsulation (Sender ↓)

L7–5 Data created
L4 + Transport header → Segment
L3 + IP header → Packet
L2 + Header/Trailer → Frame
L1 Transmitted as Bits

Decapsulation (Receiver ↑)

L1 Bits received
L2 Frame → strip header/trailer
L3 Packet → process IP header
L4 Segment → reassemble
L7–5 Data delivered to application

Data → Segment → Packet → Frame → Bits

Encapsulation = Pack | Decapsulation = Unpack

XI–XII. OSI & Troubleshooting

Troubleshoot systematically from bottom up:

Layer 1 – Physical

Cable connected? Link light? Power? Connector intact?

Layer 2 – Data Link

Local network communication? Switch? VLAN? NIC?

Layer 3 – Network

Valid IP? Correct subnet? Default gateway? Routing?

Layer 4 – Transport

TCP/UDP? Port blocked? Firewall? Connection state?

Layers 5–7 – Upper

Application running? DNS resolving? Service configured?

XIX. Quick Review Questions

  1. What does OSI stand for? — Open Systems Interconnection
  2. Who developed it? — ISO (International Organization for Standardization)
  3. How many layers? — Seven
  4. Physical Layer function? — Transmits raw bits
  5. Data Link address type? — MAC address
  6. Network Layer address type? — IP address
  7. TCP/UDP layer? — Transport (L4)
  8. Routing layer? — Network (L3)
  9. Session management layer? — Session (L5)
  10. Encryption layer? — Presentation (L6)
  11. Layer providing services to apps? — Application (L7)
  12. What is encapsulation? — Adding protocol info going down
  13. What is decapsulation? — Removing protocol info going up
  14. MAC vs IP? — Hardware/local vs Logical/routable
  15. Why useful for troubleshooting? — Systematic layer-by-layer isolation

XX. Lesson Summary

The OSI Reference Model divides network communication into seven logical layers. Each layer has a specific responsibility.

Physical → Data Link → Network → Transport → Session → Presentation → Application

  • Encapsulation: Data moves down, protocol info added
  • Decapsulation: Data moves up, protocol info removed
  • Troubleshooting: Work systematically from Layer 1 upward

Key takeaway: Don't just memorize — understand what each layer does, what it handles, and how they work together.
